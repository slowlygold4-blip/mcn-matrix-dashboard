# 登记表作品字段补齐与自动接续

本轮修复的是已授权来源的数据漏接，不是新增一套业务看板，也不把历史导入称为当天平台采样。

## 实际漏接

三份作者视频登记表原来主要走作者名单导入；原工作簿中的「抖音昵称」「作品发布时间」「点赞量」未被作品字段解析器识别。新增两组真实表头回归先复现失败，随后补齐别名，继续拒绝重复/冲突表头。原始全工作簿、物理行、行哈希和前后稳定版本校验均保留，不靠第一页或连续区域推断全表。

原自动来源服务现接入三份完整工作簿：AI 90 条、创作 13 条、切片 1,021 条，共 1,124 条作品事实。其中有 43 个点赞值、26 个播放字段和 1,027 个可解析发布日期；同作品的多来源事实去重合并，数值不能重复累加。空白仍为缺测，真实 0 单独保留。

## 日期与归属

- 日月格式只在同工作表明确写出活动周期、且有唯一有效的日历年份时解析。年份不能来自电脑当前年份、文件名或作品 ID。
- 读入时刻只用来排除未来日期，不用来填写作品日期。原表 2029、2626 等未来年份保留为字段问题；不改写成 2026。原单元格、共享年份依据及其哈希可回查。
- 新的明确日期可补充或纠正弱日期；明确来源互相矛盾时保留冲突，平台真实发布时间继续优先。
- 表题只支持已审查的三种内容标签；不能据此伪造激励赛道参与记录，不能按昵称绑定账号，也不覆盖人工标签。
- 这些表没有逐作品指标采样日期，不能把读取日或发布日期当作点赞观察日，不因此填补「今日作品点赞观测」。

## 脚本接续与资源

新增来源进入原来源服务；仍是单实例、每批 50 个短链、逐请求延迟 700ms。只读取官方公开短链跳转来补精确作品 ID，不读浏览器、不导出会话、不签名、不调用模型。ID 补齐不等于作者身份核验或点赞采样。

成功批次的待办接续改为 15 秒；网络失败仍暂停 5 分钟，拒绝/限流仍按原保护停止，不换身份继续请求。来源和发布进程共用低优先级设置，已更低的进程不被调高。没有增加计划、服务或并发采集器。

源码与正式目录同套 221 项相关测试通过，包括拒绝停止、防并发、真实 0/缺值、原始工作簿和字段保留、日历依据、未来数据、版本兼容与取消。浏览器及实际全量平台采样不在这些离线回归的证明范围内。具体入库、剩余补链和公开发布进度见维护日志；四项日常指标仍需分别验收。

## GitHub 路线核对

继续定向阅读了三个新候选，未安装或执行其代码：

- [douyin-rss](https://github.com/Xiahanjiu/douyin-rss/blob/864a6af1fb677134b3bfa744b8856ef5ad786744/app/crawler/douyin.py) 调用 TikTokDownloader 服务，缺发布时间会填当前时间，不能原样用于每日发布监控。
- [skill-douyin-rss-alert](https://github.com/JasonCai2024/skill-douyin-rss-alert/blob/bec588fb3d656a26396638e08c9f444b9eafdf23/SKILL.md) 依赖第三方接口和付费模型汇总，不符合无模型日常采集要求。
- [CreatorPulse](https://github.com/WillSoonWu/CreatorPulse/blob/d98a7918085d3823509388ce38bb9fd536d839c9/10_%E5%BD%93%E5%89%8D%E9%93%BE%E8%B7%AF%E7%8A%B6%E6%80%81%E4%B8%8E%E9%81%97%E7%95%99%E9%97%AE%E9%A2%98.md) 明确当前是模拟绑定和模拟事件，不是已接通的真实抖音采集链。未将模拟数据接入生产。

找到仓库或 skill 不算采集成功；本轮实际采用的是现有飞书授权与统一作品入库链路，修复已经查实的字段漏读和接续效率问题。
