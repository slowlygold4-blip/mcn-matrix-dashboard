# 每日发布日期口径与原表日期恢复

日常验收分别检查粉丝日变化、单作品点赞日变化、账号主页总获赞日变化，以及每天是否发布、发布几条。发布时间和指标观察时间是两条独立的时间轴，作品存量差不能用来计算当天发片数。

## 已修复问题

原表第 10、15 工作表分别保留了「原填发布时间」「原填日期」，但原统一投影仅采用第 09 工作表的推算日期。本次按精确字符串作品 ID 关联原填字段，读取已登记来源的年份范围，保留日精度、原值、行与表头 SHA；不从作品 ID 推导日期，不制造午夜时间，不把提交时间当成发布时间。

明确且一致的原填日期进入同一个作品索引。平台真实发布时间继续优先。没有日期、推算日期或互相冲突的原填日期仍保留并可筛选、查看和导出，但不能作为确定发布数。数字 `9.1` 可能是被表格截断的 `9.10`，此类歧义不自动猜测；字符串日期按原有文字解析。

## 公开契约与兼容

- 作品增加日期依据：平台时间、明确填报日期、推算日期、日期冲突、待核验或缺失。原参考日期在变更时可查看和导出；原始证据仅保留在内部，不泄露至公开页面。
- 每日发布索引的 `dateMode=publication-date-basis-v1`，每个日期、范围和内容分类均带 `{confirmed,unverified,missing}`，在上传与读取时按作品逐项复算。
- 作者每日发布显示确定记录数，同时保留待核验作品。没有完整的当日列表覆盖时，无记录仍是待确认，不能报「未发布 / 0 条」。
- 旧不可变代际保持可读；新版本的确定日期不能通过旧数据推断。消费者先上线，生产端随后输出新契约。
- 共同校验和计算集中在 `publication-date-basis.mjs`，生产端、消费端、CSV 使用相同规则。未增加模型调用、定时任务或平台采集请求。

## 真实只读复核

2026-10-31 固定截止整库比较：统一作品 80,049 条，所有非日期字段、作品 ID、归属、数值、分类和 72,901 条平台发布时间完全相同。原表恢复 3,389 个作品的明确原填日期；已有平台时间会优先，所以统一库实际新增明确日期依据 391 条，最终采用的分日结果改变 5 条。原表有 13 个冲突作品、257 行无效或有歧义的日期，继续留待核验；统一库仍有 2 条原填日期冲突、6,692 条推算日期和 63 条无日期作品。

这些是已存历史记录的日期恢复，不是新增当日点赞观测。单作品真实日常采样、全量列表完整性、未关联作者和历史缺测仍需分别验收，不能因为测试通过或发布成功而称四项采集已完成。
