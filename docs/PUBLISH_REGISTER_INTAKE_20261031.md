# 发布登记表作品指标接入修复

问题：已登记作者来源中的发布登记页使用“抖音名字 / 账号ID / 发布链接 / 点赞 / 播放量”表头。作者导入仅保留身份与链接，作品适配器又不识别这组表头，导致其中的作品累计指标未进入版本化作品事实库。

修复：作品适配器加入三个精确表头别名，复用既有整本核验、不可变原件、逐行哈希、作品去重与统一投影流程。没有指标列的作者名单仍不是作品表；重复同义列仍拒绝自动选列。短链接保留待关联状态，不用昵称或链接文本猜作品ID。

既有来源轮询器增加每来源可选 `maxExportBytes`，缺省仍为8,000,000字节；仅经核验的含截图工作簿可设到32,000,000字节。非法、非整数、超限配置在网络和数据库同步前失败。保持一份来源进程和原每日来源计划，不新增定时器或模型调用。

实际原件核对：一本5页工作簿包含4个作品登记页，465条可读取作品记录、2条无效链接；其中4行具有直接作品ID，共3个ID，另外461行短链接尚未确认作品ID。所有465条均没有明确指标日期与发布日期。完整原件约25.9 MB，主要为内嵌图片；8 MB默认上限拒绝了首次预演，没有写入。

这批数据只能作为已有累计事实和待关联作品证据，不能证明今天更新、每日作品点赞变化或当天发布条数。对齐作品、来源版本和日期后合并；重复累计值不相加，不用读取日期或工作簿修改时间伪造指标日期。不新增独立业务板块。

日常验收仍以 `DAILY_MONITORING_ACCEPTANCE.md` 四项为准：粉丝量及日变化、单作品点赞及日变化、主页总获赞及日变化、按真实发布时间去重的每日发布情况。主页成功不能代替作品成功，未得到完整覆盖不能显示“未发布 / 0条”。

验证：5个相关测试文件49项通过；既有4个不可变工作簿重新解析，事实数704 / 149 / 17 / 27,526及页级报告均不变。生产导入回执、私有原件与来源修订核验留在维护日志和私有审查目录，不提交作者明细到公开仓库。
