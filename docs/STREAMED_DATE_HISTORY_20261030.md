# 持续监控的日期历史读取改造（v124）

## 已完成并上线

旧客户端在日期分区合计超过200,000点或64MB时拒绝读取，并错误地显示“来源不一致”。4,081账号仅50个完整日期就会达到204,050点。读取器还同时保留所有JSON分区和重复的账号/日期对象Map，与9/12起无限持续积累的目标冲突。

现按最多10个、每个不超过1MB的分区一批读取，SHA/字节由原读取器核对，按代际索引顺序校验日期、账号、指标采样时间与跨分区唯一性，再写入私有紧凑列存。大范围固定数据区64字节/点，指标与毫秒时间用Float64保留安全整数，缺测用独立NaN标记还原null；真实0、负净变与采样时间不改。返回对象不暴露可变数组，任意一批错误或取消都不提交完整收据；同批请求全部结束后才返回失败。

端点、固定队列曲线、每日变化和每日覆盖使用精确索引，不再重复建立整份历史Map。CSV仍带真实端点采样时间、作者ID与来源分区指纹。小旧数组输入继续有效，严格日期/重复检查没有放松。日期验证拆为小模块，避免模型、列存和来源校验互相循环引用。

日期读取仍有明确的资源边界：紧凑数据区最多64MB、单次选中分区累计传输最多320MB；这是累计网络量，不能同时驻留所有这些JSON。超出时明确提示窗口预算，不再诬称来源损坏。历史没有删除；累计曲线保持90天翻页、原始区间起止端点不变。无日期索引的旧代际继续原有安全预算，未重写历史代际。

另修复实际长期交互缺口：统计范围超过90天时，首页末尾14天的小曲线原来没有请求齐数据。现补最近14天及其相邻日基准，保留当前/比较区间和原端点；如果当前曲线页已包含末尾窗口，不重复请求。正常4–5千账号与比较区间可在有界列存内读取；这不等于任意规模、任意网络都能无限一次性加载。
