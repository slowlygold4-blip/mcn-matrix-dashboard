# 作品归属读模型一致性与构建保留资源审查

本轮将上一轮已核验的作品发布者规则接到公开作者详情，不修改原始作者身份或原表。

## 跨页面的共同规则

`catalog.creatorSourceLinks.workOwners` 为可选的作品映射，记录原始作品行、精确作品 ID 和已有账号编号。由严格作品发布者读模型生成；源发布审核同时核对版本、原行、目录账号和真实数字编号的原生作品分区，不接受来源合成作品冒充原生证据。旧代际无此字段时兼容读取。

作者详情采用相同映射：原声明记录及数字可查看、导出，但不贡献给错误作者的指标或每日发片；已核验发布者只计一次。合成的旧账号历史不能让已拒绝的声明重新计入。保留跳转到已有发布者账号页的入口。源码中的确定性计算与运行脚本不调用模型。

同时修正两个边界：同一已核验 canonical 作者不能仅因公开别名文字不同而被误标冲突；跨北京午夜时优先采用已核验的精确平台发布时间，原登记日保留为 `sourcePublishedOn`，日期不同时标记冲突。来源观测时间不当成发布日期，未来证据仍拒绝。

当前映射覆盖原始作品总表；后续还要继续检查补充来源声明及未获严格证据的关联，不能用同名强合并作者。

## 资源审查

构建曾因历史资源累计触及64MiB上限失败，没有提高上限。依据当前Vite输出、v128–v130新增资源及完整依赖闭包，先用原校验器在临时目录验证，再删除705个可再生成的旧归档文件；原清单逐字节等于可恢复的Git版本。原归档67,078,197字节；本轮构建完成后50文件、5,194,332字节，减少61,883,865字节。未删除业务资料、数据库、原表、源码或Git历史。旧于保留范围的打开页面可能需要刷新。

仅现有发布器串行生成新代际，没有新增采集任务、调度器或并行发布器。新页面先部署，之后才启用生产映射；旧封存代际保持不变。抖音每日作品采样尚未恢复，不以本轮归属和界面改进宣称完整产品验收。
