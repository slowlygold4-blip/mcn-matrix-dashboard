# 分平台核对日常采样进度

用户确认的四项标准是粉丝及日变化、单作品点赞及日变化、主页总获赞变化、每日发布情况和数量。本轮审查发现：原顶部全站“作品部分取得”计数会混合平台，无法判断抖音作品是否在更新。主页采集成功和其他平台取得作品不能代替抖音单作品采样。

## 修改

在原采集进度面板内增加分平台明细，不新增业务页面、采集任务、调度或模型调用：

- 每个平台分别显示启用账号数、近24小时主页更新、作品列表完整与有限观察。
- 显示北京时间当日有已保存点赞观测的作品数量、已保存作品数量及涉及的账号档案数。
- 同平台同作品ID在多个历史账号档案中只计一次；不同平台ID各在自己的命名空间计数。账号档案涉及数不等于已核验作者归属数。
- 平台优先沿用明确登记。无声明而持有严格格式的抖音sec_uid定位符时可识别为抖音；显式其他平台不覆盖，昵称不参与猜测。
- 0条观测仅表示没有保存到该日的有效点赞记录，不等于0点赞或没有发布。没有数据结构或无有效上报时显示尚未上报，不补0。
- 存储计数不是平台作品全集、已通过独立来源核验的完整率或新增点赞合计。原始作品、作者、历史记录均不改写。

后台新增lib/collection-platform-progress.mjs，主接口追加rolling.platforms和dailyWorkLikes。前端以collection-platform-view.mjs白名单接收并验证，再由collection-platform-summary.tsx呈现；旧版上报仍兼容，缺字段时不拿全站值代替某个平台。

状态转发绑定上报版本、北京时间日期和窗口起点，拒绝重复平台、非法计数、超出保存作品数的观测数量以及未来或错日汇总。只发布固定平台枚举、计数和时间，不携带作者姓名、原始ID、URL、Cookie或密钥。

另修正运行明细的类型隔离：话题不能计为账号主页或作品成功，账号不能因错误的topic标记计为话题成功。真实生产只读对比中原有全站字段保持一致。

## 验证

后端10个相关文件38项通过，含8组新增平台、日期、去重和缺测回归；公开副本与后台同组通过。完整前端335项通过，含5组新增纯函数及真实组件静态渲染回归；TypeScript和生产构建通过。初次类型检查发现动态字段推断丢失，添加显式行类型后通过，未改变计数规则。

对同一只读生产事务的新旧输出比较，排除两个新增字段后完整相等；新字段穿过现有白名单转发后保持一致，数据库总写入变化为0。该次本地测量约旧0.10秒、新0.24秒，新增统计增加了读取开销；不是速度优化或完整平台采集证明。现有转发每15秒执行一次，多个公开访客读共享状态，不各自触发本机数据库查询。

真实各平台观测与来源任务状态保存在资料持有者的维护审查记录中，不把内部明细提交公开仓库。来源中“submitted”也核验了对应任务已完成，不误判为积压。

## 尚未解决

抖音作品列表访问受限仍影响单作品每日点赞和每日发布覆盖。本轮修正的是观测、去重及呈现，不能称采集已恢复。服务端正式授权/已有数据接口条件仍待确认；未购买、注册或把内部名单交给新供应商。继续停用本机抖音浏览器采集，不新建并行采集器。浏览器点击和手机验收尚未完成。
