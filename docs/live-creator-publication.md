# 作者与作品资料的自动公开发布

网页版从 v108 起支持在既有不可变发布代次中读取作者、去重作品及统计图，不再依赖每次重新构建网页更新主作者资料文件。原来的静态资料仅兼容不含这些分区的旧代次；已声明新分区时，失败或校验异常不会静默回退旧数据。

## 生产链路

1. 已授权原表经现有来源脚本进入 SQLite 版本存储。
2. 同一个来源版本投影为经营查询、账号详情和公开作品资料提供数据。
3. 现有 publisher 导出 `creator/index.json`、`creator/authors.json`、`creator/works-NNN.json`、`creator/insights.json`，逐文件计算字节数与 SHA-256。
4. 沿用现有受认证的 `/api/replica` writer 上传与原子激活，不新建定时器，不调用模型。
5. 激活前跨文件复核作品去重、条数、作者关联、累计值、发布日期和统计图。错误代次不能替换旧代次。
6. 前端按索引中的固定代次读取分区，保持原搜索、排序、分页和日期条件。内容指纹不因纯发布时钟变化而改变，避免每次新代次都重读未变化的资料。

`PUBLIC_REPLICA_EXPORT_REVISION` 为 `catalog-date-range-v7-live-creator-corpus`。旧 v1—v6 代次保持原封条；已上传的活动代次继续原有回执，完成后才生成新协议代次，不把旧代次改名成 v7。

## 代码与验证

- `lib/public-creator-source.mjs`：公开字段投影，精确作者ID关联和作品去重。
- `lib/replica-creator.mjs`：生产端与云端共用的数据契约、统计重建和激活审查。
- `lib/creator-intelligence.mjs`、`lib/source-ledger-track.mjs`：沿用网页既有纯函数；与 `frontend/lib/` 对应文件逐字节一致，由测试阻止两份实现漂移。
- `frontend/lib/source-part-reader.mjs`：带版本与哈希的动态来源读取，旧代次兼容，不在失败时偷换数据。

真实只读验证仍为 4,389 条主作者身份、18,179 条去重来源作品；不是整个矩阵全部作者的数量。主资料的严格监控关联由静态文件的548更新为3656。作品累计值及去重数量不变，读取没有写数据库。额外作者、待核身份等仍由完整名册合并，不能将这些来源身份或关联数冒称全部账号都已成功采样。

前端全量330项、真实Home浏览器刷新任务、云端SQLite/R2模拟上传/激活/旧版读回、类型检查和构建均经过验证。模拟浏览器任务不是实际用户留存实验；代码部署与数据代次激活分别核验。

## 剩余问题

抖音作品完整HTTP覆盖尚未解决。补充表 foundation 的独立静态资料仍需接入同类自动发布；新来源中完全未出现在主作者表的身份还需索引归并。新网页版本上线不等于新数据代次已到达公网，以实际发布回执和分区读回为准。所有采样缺口、未明确日期和冲突继续留空或保留待核，不伪造历史。
