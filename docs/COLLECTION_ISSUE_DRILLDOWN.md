# 采集问题名单：同一状态截面

顶部采集状态使用全局已启用目标的近 24 小时覆盖，不随页面矩阵、分类和观察日期变化。问题名单必须与这份状态使用同一截止时间、同一目标集合，不能用账号页的 8 小时覆盖代替。

## 数据链路

`lib/collection-progress.mjs` 在已有覆盖集合上投影本地目标编号，不另执行采集或按昵称匹配。`rolling.issues` 包含 `version: 1`、`since`、`asOf`、`missingProfileTargetIds`、`missingTopicTargetIds` 和 `workIssueGroups: [{code, targetIds}]`。

- 两类未更新目标的唯一编号合计等于 `rolling.notUpdated`；作品问题组的唯一编号合计等于 `rolling.workIssues`。
- 名单只携带目标编号及固定错误码；账号名称来自已发布目录，不传登录态、原始接口消息或主页定位凭据。
- `frontend/lib/collection-issues.mjs` 供生产者心跳和前端共同验证，校验 24 小时时间窗口、正整数编号、重复及计数，不通过就拒绝整份新证据。
- 旧版心跳没有名单时保持兼容，不能渲染成“没有问题”。

## 传输和访问

仅已认证生产者的 `heartbeat` 请求可以达到 256 KiB；其他操作保留 16,000 字节上限。名单最多 32 个问题组、单列表 20,000 个编号、总计 30,000 个编号引用；超出拒绝，不截断后保留原总数。未知错误码转为通用原因，不回显原始文本。

访客只读取问题名单。打开名单、搜索、翻页、查看账号均不下达采集指令；“全量采集”仍走原有单独的会话鉴权与去重队列。

## 展示边界

打开名单时保留该状态截面；后台轮询出现新名单时提示重新读取，不在用户浏览中静默替换行。未出现在已发布目录中的编号保留，并提示暂无公开详情，不假造账号链接。话题和账号分开标注。

作品采样提示不是“今天没有发布”，主页成功也不是作品全集已取得。此交互不提高或伪造任何采集成功率。
