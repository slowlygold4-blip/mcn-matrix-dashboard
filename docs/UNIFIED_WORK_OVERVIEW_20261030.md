# 统一作品汇总与每日发片联动审查 · 2026-10-30

本阶段解决首页的一个实际断点：每日发片已经合并来源记录与平台作品，作品成绩汇总仍只统计原总表。现在，原有每日发片区域接入同一套作品指标采用结果，按发布日期和内容分类一起筛选。

## 已实现

- 作品按ID唯一归并，来源记录是同一作品的证据，不再作为另一个加数。导出与本地经营查询复用同一取值函数。
- 累计点赞、累计播放记录、已收录作品数及未记录发布日期的数量同时呈现；每项显示有值/缺失条数。累计数不解释成日期区间新增。
- 首页只读汇总索引；点某个发布日才读该日分区。无需为一个合计拉取所有作品历史。翻页不缩小总计，作品表可切换正序/倒序，缺失值始终放最后。
- 日期区间改变时同步图表和汇总，已超出日期范围的明细关闭；内容分类同时影响数量、汇总、图表和明细。一个作品可有多个明确标签，但在全部内容里只计一次。
- 旧发布版本缺少合并指标时显示“当前版本尚未提供”，不回退到总表子集冒充全量；原始登记/来源核对保留在折叠区域。
- 发布端逐日、逐分类和全局复算全部明细，拒绝根合计被篡改、跨日期重复ID、缺失/混合指标版本。客户端读取某一天时再次核对该日合计。

以上不是新采到的数量、完整平台覆盖或区间新增播放。没有发布日期的40条保留在入口中；指定日期区间时不猜日期塞入。播放记录没有被当作逐条独立核验的平台真实播放。后续真实采样与导入会使新版本数字变化，不能要求它与此固定快照永远相同。

真实库在只读事务内核验，另用直接BigInt求和复核；全部142个作品分区通过跨分区审查。没有写入数据库、发起平台采集或模型调用。实际读取约9.5秒，**没有把这个时间报成性能优化成功**。

## 验证范围

- 完整前端391项通过，包含实际组件排序、分页、缺失/零值、日期和分类切换、刷新保留、失败重试、键盘、移动布局与减少动态效果。
- 相关后端121项通过；公开源码副本96项相关检查通过。测试数量存在重叠，不能相加成覆盖率。
- TypeScript与生产构建通过。新增反例包括同作品多标签不重复累计、未知不补零、同时间冲突留空、安全整数溢出、伪造合计与混合新旧明细。
- 开发中发现选中日期区域缺少语义角色，实际浏览器用例暴露后已修复。没有访问抖音网页。

## 仍未完成的整体目标

1. 当前主页采集能持续保存数据，但完整作品HTTP采集与话题双指标当天覆盖仍有缺口；本阶段不声称提升采集成功率。
2. 作者身份关联、未取得的历史日期、完整作品覆盖仍需解决，不能通过补零消除。
3. 统一作品汇总接入了原每日发片区域；原始来源审查视图继续保留其原始含义，其他全局产品任务仍需后续审查。
4. 查询成本和发布进程峰值内存仍偏高。没有删除用户数据、原表、历史或来源记录，也没有据此宣称全部代码债务已清理。
5. 没有新增定时任务、额外全量采集或运行时模型调用；沿用原受管发布器。整体开发目标保持未完成。
