# 主页覆盖必须有真实入库指标

本轮针对四项日常标准核查进度面板，未把本轮修复称为抖音全作品采集恢复。

## 复现的问题

`deriveCollectionHealth` 允许两个已知主页指标成为 `available`，调度器此前直接把这个状态写成 `profileUsable=true`。进度面板又用批次详情标记计数，所以缺粉丝、缺总获赞或缺作品存量的记录，可能被报成“主页三项成功”。有状态标记但没有对应快照/审查记录，也可能计入覆盖。

固定回归中，旧代码将7个账号计为主页成功；实际只有2个当前启用账号具备完整、同批且时间有效的入库证据。另一回归复现了总获赞为null、其余为真实0时仍标记主页齐全的问题。

## 实际修改

- 调度器检查粉丝、主页总获赞、作品存量三项非负安全整数以及有效质量/主页状态。真实0有效；缺一个指标仍保存其余值，完整主页标记为false，不拒绝或改写原采样。
- 近24小时主页覆盖通过目标、同批审查checksum和快照关联计算，核对实际采样、审查、批次起止及当前截止时间。不信任旧批次里的布尔成功标记，不回写历史详情。
- 跨越24小时的正在运行批次，仍保留其窗口内已经提交的有效快照；未来观测、未来审查、错误checksum、坏计数和拒绝质量不计入。
- 当前滚动范围排除暂停账号；历史整批结果保留当时已经采过、后来暂停的账号。两者不混用。
- 话题、作品列表完整性、单作品点赞及相邻日可比情况保持各自的原有统计；完整主页不代表其余维度成功。SQL关联和接受状态属于已保存记录的核对，不等于重新向平台独立核验原响应。

接口JSON和前端结构未改，没有新增数据板块、网络采集请求、定时器或模型调用。粉丝和总获赞的日变化仍按各自真实相邻北京日观测计算；主页作品存量不是实际发片数。

源码与正式目录各26文件230项相关测试通过；包含调度、归一化、分析、进度、作品重试及入库审查。旧进度测试中仅提供成功标记的正例已补上实际快照和审查凭证，另保留“标记有成功但缺凭证”的反例，未靠保留无证据的旧期望规避修复。

## 实库核对和未解决项

一次固定截面的只读对比中，修复前后均为4071/4081个启用账号有近24小时完整主页记录，未抬高成功数；抖音4057/4067，B站14/14。该次旧读取约275ms，新读取约297ms，进程RSS约133MB，仅是一次本机观测，不是性能保证。正式数据库0写入。

北京时间2026-10-31当日抖音和B站单作品点赞观测仍为0，不能把过去24小时主页覆盖称为当日四项齐全。抖音完整作品、合法接口授权、来源身份缺口及产品审查积压仍未解决。源码测试、生产API回读和界面验收必须分别记录；本轮不宣称已完成浏览器或手机验收。

## 本轮GitHub路线检验

通过agent-reach的GitHub CLI读取了[you-get抖音实现](https://github.com/soimort/you-get/blob/049548f3f3f35e67ba8d3181c71fdc71d11cf260/src/you_get/extractors/douyin.py)和[bilix抖音实现](https://github.com/HFrost0/bilix/blob/bb5b234cdfe3fafc4db9d992b91091f2edf791e5/bilix/sites/douyin/api.py)。两者均有旧版`web/api/v2/aweme/iteminfo`单作品路径，不能枚举作者全集；you-get该文件最近一次修改记录是2022-10-17，不能把仓库仍存在当作接口仍有效。

使用一条已有作品记录，对you-get所列公开域名路径做1次普通HTTP请求；HTTP200但不是JSON，未取得作品。无Cookie、签名、浏览器、重试、身份切换、视频下载、模型调用或入库，不接入这条未验证的方法。现有官方视频列表隔离工具的就绪检查仍显示token、open_id及scope未配置，未擅自获取凭据。不能靠反复换skill名字把缺口报告成解决。
