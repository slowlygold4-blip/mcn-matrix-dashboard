# 团团全量作者监控接入

## 运行方式
- 采集、作品证据核验、身份关联、首次采样与后续轮巡均由本机普通脚本执行；不调用 LLM，不消耗模型 API token。
- 受管服务为 `com.codex.douyin-monitor-workbench`。需电脑开机联网；电脑离线时不能采集，恢复后只记录真实采样时间。
- 身份核验与既有主页/作品采集共用受控执行通道，空闲时给新增作者保留执行机会；每轮最多两位，分别给来源全量队列与其他队列，保留冷却和租约。
- 来源任务成功后：验证同一作品、提交抖音号、平台作者规范 ID → 原子保存核验凭证 → 启用目标 → 自动首次采样 → 持续轮巡。
- “排队”不等于“已采到”；主页统计、作品列表完整性分别核算。空值与缺测不补零。

## 全量入队工具
`scripts/enqueue-creator-source-resolution-candidates.mjs --all` 只读预演。`--apply` 需绑定原始来源 SHA、独立一致性备份，且校验当前库/备份/冻结原始文件一致。
`--recover-failed` 只为所有旧身份任务都已 rejected、且总表中另有未使用作品证据的作者创建新任务。不覆写旧任务，不擦除失败历史，不重复提交同一证据。
`scripts/audit-full-roster-monitoring.mjs` 在同一只读事务下，从当前数据库的账号、原始来源、补充来源和待关联名册生成逐人审查；不读取旧静态JSON，也不把作者总数写死。复用公开看板的分类和名册去重逻辑，当前名册仍含未独立核验的平台身份，不能把名册条数当成采集成功账号数。

```sh
# 默认读取当前项目数据库，生成北京时间日期+毫秒时刻命名的报告
node scripts/audit-full-roster-monitoring.mjs

# 对指定数据库做只读审查，不迁移或创建数据库
node scripts/audit-full-roster-monitoring.mjs --database /path/to/monitor.sqlite --out /path/to/new-report.json
```

报告文件权限为0600，含内部作者信息，不能提交到公开仓库。既有文件拒绝覆盖。命令行只输出汇总；不启用账号、不重排队、不采集、不调用模型、不新增调度。`MCN_SITE_ROOT`可显式指定线上前端源码目录；未指定时优先本仓库`frontend/`，再检查私有工作区的相邻`mcn-public-site/`。显式指定错误时直接失败，不偷偷改用其他目录。

状态含义：`monitoring`仅表示已有启用的监控关联；`paused`是无身份冲突凭证的停用；`identity_conflict_paused`要求存在明确暂停记录；`identity_conflict_active`暴露不应启用的冲突异常。其余状态分别表示排队解析、存在已解析候选但待核验关联、历史解析失败、待定位及标识修复。任一状态都不代表作品已全量采到。全局队列项数和逐人分类分开列出，多个来源任务不会被算成多位作者。

## 公开端同步
本机受管发布器每次发布一致性数据截面，catalog 同步严格一对一的作者行与监控目标关联。
`lib/live-author-links.mjs` 校对来源修订、修改时间、原始行数后，用动态关联替换冻结关联；不修改作者资料与作品指标。新目标回到原作者行，不另外增加一位作者。
导出期间仅在同一 SQLite 事务内复用严格身份核验，写入或结束导出立即失效，防止重复遍历整批证明导致高 CPU。

## 尚未打通的入口
- 仅抖音号、无可核验作品或主页：自然用户搜索 + 主页接口交叉核验原型已实现，三次真实试采均在搜索阶段超时。没有接入自动生产队列，不以昵称猜配。
- 旧失败作者：部分可从原表找到其他作品，已追加恢复队列；无新作品证据者不无限重放同一 403 请求。
- 身份冲突暂停：保留暂停，必须取得新的同人证据再解除，不能用“全部启用”掩盖串号。
- 来源标识错列/缺失：保留原值；已修正同名 Markdown 自动链接的 ID 识别，其余候选待独立证据确认。
