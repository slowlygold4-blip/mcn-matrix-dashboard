# B站已登记作品的持续指标更新

账号投稿列表和单条公开作品详情是两种独立观测。列表读取失败时，不能据此把作品数记为零，也不能丢掉已经登记的作品 ID。

原有账号采集流程现在会从数据库准备最多 6 个本账号的已登记 BV。若没有取得投稿列表，则对这些已知公开作品读取官方详情；逐条核对 BV 和作者 UID 后保留实际响应时间、点赞、评论、分享、收藏和实际播放字段。来源仍是官方 HTTP，运行时不调用模型，不启动浏览器。

- 选择顺序兼顾最近成功点赞观测和实际尝试时间。失败作品也会轮换，避免少数失效 ID 永远占满名额；未发出的延期请求不记为实际尝试。
- 投稿列表的错误和状态原样保留；补采不会把列表改成成功，也不提供受限列表或证明当天没有新投稿。
- 单条详情拒绝后，本批停止后续详情请求；本地已知 ID 不能成为新的列表观测、指标或采样时间。
- 真实零点赞保留为零，缺失保留为空；作者累计获赞来自作者卡片，不从这几个作品合计。
- 有效投稿窗口按原流程处理；明确零库存且成功读到空列表时，不用旧作品覆盖零库存判断。
- 覆盖始终是部分观测。完整每日发布数量仍需要独立、完整的投稿列表证据。

该路径复用现有串行账号调度和数据库事务，不新增定时任务。启用需要主服务加载更新的 provider；不能仅凭文件已复制就声称运行中服务已经使用新逻辑。

验证：`node --test --test-concurrency=1 test/bilibili*.test.mjs`，覆盖轮换、真实零、跨作者拒绝、失败停发、独立响应时间、保存和每日计数。
