# 日常监控四项验收标准

本标准以用户 2026-10-30 的明确要求为准。监控从北京时间 2026-09-12 持续积累；导入表格、授权接口和脚本响应都进入统一作者与作品索引。来源记录在后台保留，不另设一套相互重复的业务总量。

| 日常要看的内容 | 记录与计算 | 缺口显示 |
| --- | --- | --- |
| 账号粉丝量与变化 | 留存实际采样时间、粉丝量；本日与前一北京时间日均有有效值时，取两天各自末次有效值相减 | 缺本日或前日值时显示缺测，不能填零或拿不同日期冒充相邻日 |
| 单作品点赞与变化 | 以平台和精确作品 ID 去重，校验作者归属；保留每次真实点赞观测及时间，按相邻日相减 | 没有新的作品点赞观测，不能拿主页成功或历史累计值当成本日成功 |
| 账号总获赞变化 | 对账号主页总获赞独立留存、独立计算相邻日净变化，保留负值 | 不能把最近若干作品的点赞和称为账号全部总获赞；主页值缺失时不推算 |
| 每日发布情况 | 按作品实际发布时间转北京时间或一致的明确填报发布日期、按作品 ID 去重；展示是否发现发布、已发现几条、可查看哪些作品；推算或冲突日期保留待核验，不计作确定发布数 | 有记录且覆盖不完整时显示“已发现/至少 N 条”；无记录但覆盖不完整时显示“待确认”。只有该日覆盖已确认完整且没有作品才显示“未发布 / 0 条” |

发布时间用于判断哪天发布；指标采样时间用于判断哪天的点赞量。两种日期不可互换。作品存量净变化不能代替当天发片数。

每个指标分别保留真实零、减少、缺测三种情况。周/月汇总标明可比账号和起止采样日期；不同账号缺测不能悄悄当零加入变化。播放量不参与这四项验收，估算播放不能当实测数据。

同一作者的 UID、短号或公开抖音号只有在原表和已验证身份关系明确时归并；账号合并不重复累加作品和观测。不按昵称猜归属，不覆盖人工分类、原件或历史记录。

运行中的采集、排队、去重、入库、计算和发布由普通脚本执行，不调用模型。开发与审查对话和运行时任务的消耗应分开说明。生产启用不代表四项覆盖全部成功；作品接口失败、身份待关联、当天缺测及最后实际采样时间必须能查到。

本文件是验收要求，不是“全量采集已经完成”的证明。实际状态以当前快照、逐项覆盖、作品明细和公开发布回读为准。
