# 来源身份与名册一致性审查 — 2026-10-30

## 实际问题

来源任务显示“已提交”不等于仍在运行。本轮选定任务 720392b7-388a-4f50-b07e-7e7bebc8bf82 已于 10/30 北京时间零点后处理完成，保存了 807 行。历史回执中的“538 行复用、269 项待审查”是导入当时的行/事项计数，不是今天的独立作者接入人数；不修改这个历史回执。

进一步发现两个读取入口采用了不同的身份关系：公开数据基础层使用有效的来源身份回执和当前官方主页证据，主名册/导入接入检查却主要沿用改号历史关联。因此，同一作者在数据基础层已经有关联，在另一处仍可能显示待关联。不能用“任务已处理完”掩盖这一问题。

## 修改

- 提取 `source-profile-targets.mjs`，让数据基础层和名册复用同一个来源身份读取器，删除原处重复逻辑。
- 名册复用现有合并器，把经过核验、主题一致、锚点不冲突的来源资料关联到已有账号。来源行、原名称、二级分类、来源作者行索引均保留；不按昵称猜关联，不创建或启用账号。
- 保留所有拒绝条件：多账号声称同一身份、来源回执损坏、来源内容被改、不同大主题、不同主页、未决身份更正，都不能靠新鲜证据静默绕过。损坏的持久回执也不能被临时新鲜度回退救活。
- 不修改原始任务、回执、来源原件、历史指标或目标设置。采样新鲜度和作品完整性仍独立判断，关联本身不代表采到作品。

## 验证结果

1. 同一只读数据库快照中，175 条重复待关联资料合并到既有账号；42,575 处来源行坐标全部保留，原账号标识全保留。不同的已绑定 target 集合仍为 4,128，没有创建新账号。这是视图关联修复，不是新增监控成绩。
2. 选定来源的当前接入检查，692 个有效提交身份中，从 334 启用、2 暂停、356 待关联，变为 479 启用、2 暂停、211 待关联；变化是 145 位原已存在账号被正确呈现。暂停状态不变，剩余身份不猜绑。以上为固定时刻的只读对比，不是今后实时数字。
3. 公开数据基础层提取前后，在同一时刻/事务、相同参数下完整投影 SHA256 相同；原本已正确采用的身份、指标与来源没有被改成另一套规则。
4. 18 个相关测试文件、181 项测试通过，包括本机 HTTP 鉴权路由、缺失值、原始来源保留、过期持久证据、被修改来源、冲突与人工更正、暂停及分类保持；测试不启动浏览器。

首轮回归发现旧的精简数据库没有 provider 字段，新层在无可验证证据时仍进行了不必要查询。已改为没有身份映射就直接保留原视图，不降低验证门槛。另一个 HTTP 测试在未改代码的正式目录也失败：旧断言只允许显示一个监控账号，而当前产品已保留来源作者行；修正为同时断言一个监控账号、一个来源作者，且经营汇总不变，不再要求隐藏来源作者。

## 发布与边界

代码已同步正式目录并在那里通过相同测试。主服务和公开自动发布的实际加载/激活证据记录在本轮私有维护日志，不能用同步文件或绿色测试替代实际发布确认。没有新增定时任务、采集器或运行时模型调用。

本修复没有恢复抖音完整作品采集。每天粉丝、每条作品点赞、主页总获赞及其变化，以及实际发布作品数量，仍须分别核验；缺测不补零。来源中未解决的身份、受限填写表单和完整采集仍是未完事项。来源日常检查正在使用现有授权读取链路进行，不把“脚本活着”当成来源全部读成功。
