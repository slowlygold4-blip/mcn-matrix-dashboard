# 公开源码独立开发与验收修复

## 已完成

上一轮公开源码299项测试中，有17项依赖本机未公开的静态发布文件；默认TypeScript检查也直接引用不存在的Sites生成配置/模块。仅把源码上传并不能让开发者正常启动。

现支持两种明确的运行方式：

- 干净克隆自动使用独立Vinext模式，`npm ci`、`npm run dev`、`npm run build`、`npm start`和`npm run typecheck`可执行。复制.env.example为.env.local后，通过MCN_READONLY_ORIGIN读取已有公开副本；未配置则明确失败，不生成业务样例或补零。
- 完整Sites脚手架继续使用原托管配置，原配置全文保留在vite.hosted.config.mjs。发现托管配置但缺文件时明确报错，不静默变成另一种部署方式。已同步回托管源仓库并构建、发布v125，避免下次源码导出覆盖掉公开仓库的修复。

独立数据转发只允许两个API的GET/HEAD。所有写操作拒绝；不转发Cookie/Authorization，不跟随跳转、不登录、不重试，不接受访问者传入的上游URL。上游地址仅来自服务端配置，HTTPS根地址或本机HTTP根地址；每次有20秒整体期限和8MB响应预算，保留数据SHA/截面头，拒绝非JSON或超额响应。它没有管理授权或采集能力，也不是一套新增生产数据库。

## 测试与真实来源验收分开

默认`npm test`选择非浏览器测试文件，合成样本包含多内容类型、跨表别名、来源未关联、日期缺失、真实0、指标缺测与同值/冲突观测；原先依赖本机文件的17项断言继续覆盖去重、统计、来源校验和隐私字段，没有改成skip或删除掉。测试规模不再写死为旧表4389作者/18179作品。显式`npm run test:browser`单独选择浏览器用例；本轮未运行浏览器验收，部分旧浏览器用例的资料依赖仍需单独整理。

`npm run test:published -- --directory /absolute/private-export/public`是资料持有人显式执行的来源导出验收。没有目录直接返回失败，不自动读这台电脑的业务文件。工具核对30份真实旧导出的修订、字节/SHA、声明条数、唯一作者/作品、派生统计、敏感字段和补充表；旧分区只有revision/items的格式仍受同一seal和计数约束，明确version=2则拒绝。普通回归不复制业务数据到仓库。

该来源验收不等于已核验真实播放、平台逐条采样或当前全量监控。最新平台数据仍须另外检查采样时间和覆盖。
