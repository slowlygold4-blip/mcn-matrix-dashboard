# 原始总表与补充表的作品发布者统一规则

## 问题

同一个抖音作品 ID 在不同来源的作者声明可能不同。已有经营读模型对补充表使用唯一、严格核验的平台发布者，但对最初总表没有完整应用这条规则，导致作品仍挂在原声明作者或空账号上，后续有效平台指标也无法采用。

## 修改

原始总表和补充表现在复用同一作品发布者规则。候选仍须通过既有 `strictPlatformPosts` 检查：来源作者与当前监控账号的正式关联、平台和 canonical 定位、数据库作者锚点、原始响应作者锚点、精确作品 ID、有效时间，以及全局唯一的平台发布者。新增观测时间检查，未来观测不能改写历史归属。

这只修改统一读模型中的作品归属，没有合并作者身份、改写原始来源或启停账号。原声明账号保留为 `sourceAccountId`；不同声明标记 `sourceOwnershipConflict`。归属冲突时沿用原有补充表的保守指标规则，不把旧作者声明下的累计值当成新作者的有效指标；原始数字仍在原表与原始来源记录中，没有删除或写零。真实有效的平台指标按已有采用规则更新，缺少指标仍为空。

原声明数字另保留在 `sourceClaimedCumulativeLikes` / `sourceClaimedCumulativePlays`。没有有效替代值时，采用状态明确为 `conflict`，沿用现有冲突计数和显示契约，不把“有数据但归属冲突”伪装成“从未提供数据”。

同名不构成绑定证据。同作品在两个严格平台作者下面出现时，保留原始历史，统一模型不强选一个作者。无有效原始作者响应、未来观测、未知作者仍不能通过。

## 验证

- 新增两个回归组：最初总表跨作者作品归属，以及未来观测、重复平台发布者、缺原始作者证据的拒绝情形。改动前首个回归复现旧作者未更新的问题，修改后通过。
- 10 文件 150 项直接相关测试；7 文件 71 项导出、历史、分片及公开读取测试；后台同一组 17 文件 221 项通过。均为本机合成/只读数据验证，不是平台采样成功率。
- 同一真实数据库只读事务新旧比较：统一作品总数保持不变；明确纠正 133 条作品发布者，并逐条核验其既有作品 ID、原始作者、当前 canonical 锚点和观测时间。原始数据未写入。另有仅增加原声明审计字段的记录，不算作新增作品或采样。
- 分片测试的公开源码默认路径修正为优先仓库 `frontend/`，仍尊重显式 `MCN_SITE_ROOT`。跨前端路由测试需要其开发依赖；本轮使用已有完整安装、且相关五文件与公开副本一致的前端，没有重复安装整个依赖目录。

本次不修改前端代码或采集服务。后台文件更新后，由已有串行发布流程在下一新数据代际加载；已经封存或正在上传的旧代际保持不变。源码验证、数据封存和公开可见是三个阶段，不能把源码通过说成已公开生效。

## 未完成

源作者名单中相同作品的关联声明仍需持续核验；不能仅依据名字或一个 ID 碰撞就合并账号。原始作者作品弹窗与全局规范归属之间的追溯展示还需接续检查。抖音每日单作品采样、每日发布完整覆盖和部分作者身份接入仍未解决；本次不产生新平台数据，也不代表完整产品验收通过。
