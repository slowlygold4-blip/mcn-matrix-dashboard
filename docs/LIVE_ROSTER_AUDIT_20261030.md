# 全量名册审查工具修复

## 已修复的问题

旧工具在源码里引用相邻前端目录，从该目录读取静态`authors.json`等文件；这些文件可能落后于当前入库。默认输出还固定为10月26日报告并直接覆盖，所有停用账号都被归入身份冲突，同时为获得账号列表生成了包含指标历史的完整产品报表。结果既不便移交，也可能让开发者依据旧名册诊断新问题。

新版从同一数据库读事务读取当前账号分类、主来源、补充来源与待关联名册，使用线上同一`buildTuantuanRoster`函数去重。分类基础投影与公开导出共用，删除工具内的完整经营报表调用和静态JSON依赖。主名册在同一投影中复用一次，不引入长期身份缓存，不削弱关联证据或更改用户分类。

停用和有明确身份暂停记录分开；意外启用的冲突目标会标异常。无有效ID的记录仍保留。来源的`targetIds`与符合当前主题的账号关联同时留存，以便定位分类/关联问题。原始错误信息在报告输出中去除凭据、网址和本机路径，原库错误记录不变。

输出采用北京时间日期/时刻、0600权限、独占新建。公开源码目录优先使用本仓库`frontend/`，也允许明确指定`MCN_SITE_ROOT`；不再强制每位开发者建立同名相邻目录。命令导入时不会自动访问生产库。
