|---|---|---|
| 1. 脚本成功率 | 原有采集/来源服务保留；审查分开记录批次、北京时间当日与近8小时主页覆盖 | 完整作品采集仍受限，不能把主页成功或一次微批成功称为全量成功 |

| 4. 数据是否全部可见 | 修复补充来源不进入发布台账，并接入已有严格身份凭证支持的作品 | 全量作者身份、所有作品和缺测历史仍未解决 |
| 5. 计算正确性 | 列表与本地经营读口的作者/分类/日期合计采用同一字段值；同作品不重复累加；安全整数溢出不输出不精确数 | 有些记录没有指标采样时间，不能据发布日期或提交时间补造每日增长 |
| 6. 结构与测试债务 | 将基础来源版本读取从混合经营模块分离；前后端复用同一取值算法；修正旧存储测试夹具 | 未删除或重构全部遗留采集器；发布进程内存与全量读取成本仍需优化 |
| 7. 汇总与自动维护 | 已使用原来的发布器推送统一发布台账；来源轮询器不重启，不新增定时任务 | 自动维护链路仍有真实采集/授权缺口，不宣称全量持续监控完成 |

## 本轮发现并纠正的关键时间错误

原 `public-table-foundation.mjs` 将第10张表第14列解析成 `observedAt`。直接核对保存的原始表头后确认，该列实际为 **提交时间**。因此这3,884条记录不能凭该列日期覆盖已有指标采样，更不能用于计算每日增长。

本阶段早期版本沿用了该错误解释，已经撤回这项采用规则并部署纠正。不能把早期的“较新观测”试验结果作为最终成功证据。最终实现：

1. 按原始列头明确区分 `metric-observation`、`submission-time`、`unknown`。
2. 只有明确标注的指标采样时间才进入有日期的比较；旧发布数据未说明含义的时间也按未知处理。
3. 提交记录保留原数值与记录时间。已有有效采样不会因提交时间较晚而被覆盖。
4. 没有其他已知值且提交记录数值唯一时，可作为未注明采样时间的累计参考；不生成虚假的采样日期或日增长。
5. 相同作品、相同明确采样时间的矛盾数值保持待核，不选择较大值。提交记录无法判定唯一值时同样保留待核。

真实反例复核：已存指标442，提交记录395。纠正后列表与合计均为442；395及其提交时间保留在证据中，未被当作新采样。来源行数字和身份投影没有改写。

- `lib/creator-source-corpus.mjs`：基础来源版本及原有严格关联读取；不依赖后续补充投影，消除循环依赖。
- `lib/creator-source-operating-view.mjs`：已有数据按作品ID归并；查询在一致读快照内执行，原始累计证据保留。

- `lib/public-table-foundation.mjs`、`lib/replica-foundation.mjs`：时间含义来自原表头，公开契约保存记录时间与类型，同时兼容旧数据读取。
- `frontend/components/author-unified-works.tsx`、`unified-work-metric.tsx`：列表、筛选合计与证据详情。

原始记录、历史数据库、表格版本与用户修改保留。此处合并是脚本计算，没有运行时模型调用。
