# 补充来源作品发布者一致性

补充来源的作品与原总表属于同一个作者/作品集合。修复前，总览按核验发布者归属，作者详情却仍可能让原声明人与实际发布者各贡献一次；本轮接通同一条归属规则，不修改原表或合并作者身份。

## 契约和计算

可选的catalog.creatorSourceLinks.foundationWorkOwners使用精确contentId及已有targetId，与原总表workOwners的workRow命名空间分开；foundationWorkOwnerRevision绑定来源内容指纹。同一来源内容跨发布时钟被页面缓存复用时仍可核验，内容改变或未来版本则拒绝。补充表不伪造原总表行号。映射必须出现在同一已核验foundation版本的作品集中，且不与原总表覆盖重叠。

两类映射共享auditWorkOwnerNativeEvidence：核对清单中的账号、分区类型与targetId、版本和截止时间，以及精确作品ID对应唯一真实数字编号的平台作品。合成来源记录不能充当平台证据；旧代际没有映射时不会增加原生作品读取。

作者详情保留原申报声明和来源记录累计值，未获采纳的数字不贡献指标或每日发片。实际发布者只计一次。CSV保留未采纳累计记录及其时间依据，提交时间仍不会变成指标采样时间。账号之间不会因作品重复而绑定为同一个作者。

## 验证与边界

合成回归覆盖来源缺失、重复、账号错误、来源命名空间冲突、分区版本和时间错误、合成证据、旧代际兼容，以及申报累计值在CSV保留但不进入采纳指标。真实封存代际只读对照表明对应作品重复贡献被消除，原声明仍可追溯；没有改写数据库、原表、来源分片或历史。具体业务数量及线上发布回读证据保存在私有维护日志。

本轮是统一数据归属修复；抖音每日作品采集、完整列表覆盖和其他尚未接通的作者归属仍需要继续处理。测试或界面发布不等于全量采集恢复。未运行本机抖音浏览器、购买服务、调用模型或另起并行采集。
