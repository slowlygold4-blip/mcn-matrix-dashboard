# 补充表作者身份留存与自动导入审查

已定位的问题：补充表的已匹配作者依赖24小时内的主页样本直接关联；样本变旧或之后取样失败时，关联从读取结果中消失。原始表格没有丢失，但账号、作品和每日监控的连接会不稳定。13:10Z只读真实库的离线反事实比较中，129位补充作者有45位已关联，其中43位的关联不能跨越样本新鲜度窗口。该比较不是未来采样。

## 实现

- 追加 `supplement_profile_identity_receipts`，记录实际完成来源任务、完整请求SHA、来源键、源任务起止时间、明确提交ID、原主页snapshot/audit/run和真实准入时间。不复制大JSON，不改原始表格、不把来源任务伪造为已核验作品。
- 原总表与补充表共用严格历史主页核验与冲突保留规则。新准入仍需真实且新鲜的官方证据；准入后暂停、改名、离线不撤销历史身份。已核实UID冲突不能由后来失败清除。
- 明确来源版本、请求字节、任务状态或身份凭据变化时停止使用旧回执；被拒的持久回执不能被新鲜度临时读取路径绕过。新版本重新核验，原回执留存。
- 重复作品行、多个重叠来源按明确账号去重；不同提交ID争用同一账号、抢占另一已确认作者的目标均拒绝自动合并。账号启停和主题保持原值，主播不会因导入声明被强行归团团。
- 提取现有当前来源版本读取器 `table-source-jobs.mjs`，统一导出与准入使用相同的版本选择及原始请求，保留原先元数据预选、流式遍历和异常JSON语义。
- 全库验收再发现一处真实例外：原总表ID内有误写的Markdown链接片段，严格核验已识别并保存身份，但补充表展示索引仍用原字符串作键。新增端到端回归先复现，索引改用同一已核验ID归一化规则；原单元格及历史拼写不变。临时库未包含该账号的其他新鲜样本，未能单独发现此例；全库验收不能被临时库测试代替。
- 接入既有启动备份门禁、采样审查提交后，以及作者来源导入COMMIT后的路径。不新增定时任务、采集进程、平台请求或模型调用。来源提交成功不因随后关联失败被标为导入失败；已提交原总表关联也不受补充表失败影响。
- 新证据表纳入一致性备份计数；旧备份仍可读。默认每次最多200项，剩余数仅指符合准入条件的候选，不能称所有未关联作者已解决。
