# 持续采集的小批串行调度

生产持续模式每批最多接纳 64 个当前到期目标。每批完成后释放调度入口，由现有 30 秒循环重新读取完整名单、已提交快照、失败退避和身份规则。没有新增轮询器或并发采集器。

话题优先保存。账号按平台交替接纳，同平台优先久未尝试的目标；缺失或异常尝试时间不会把目标永久排到队尾。平台路由复用既有 `targetPlatform`，不推断作者所属矩阵或改动分类。失败探针保留原失败时间和状态，自动探针至少等待 15 分钟再重试，防止小批次放大请求；手动探针失败不会压制自动检查。

64 是单批工作量，不是名单上限。未接纳目标继续留在完整到期集合；本批成功结果按真实采样时间保存，后续批次和服务恢复读取相同持久证据。手动“全量采集”和“刷新快照”保持完整请求范围及回执；历史定时模式也不改动。

该改动解决长批次冻结名单和小平台排在大名单之后的问题，不提高平台接口授权、不绕过拒绝，也不证明全部作品采集成功。主页统计、作品点赞观测与完整作品库存仍分别统计。64 个慢请求仍可能耗时较长，没有固定时延保证。

验证包括真实调度器与内存数据库的 70 人跨批恢复、新增作者、失败退避、手动完整范围、实际串行平台顺序；另有生产只读规划对比。合成采集响应不代表真实平台成功率。
