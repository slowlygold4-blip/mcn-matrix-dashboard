# 来源资料如何自动进入同一个后台

原表、上传表格和平台采样都是数据来源。原始记录保留，展示前按明确账号/作品标识核对和去重；没有对应实测的指标保持缺测。

当前更新路径：

1. 已有导入和每日来源脚本把新资料写入主库，保存原件、版本、真实来源时间。
2. 现有发布脚本检查已完成的作者导入、总表版本、作品来源版本和采样回执。即使本次只有名单变化、没有新的账号采样，也能检测到更新。
3. 同一读事务生成账号目录、作者作品、补充来源和统计分区。已知作品 ID 只保留一项；补充来源与主作品集再核对，避免重复累计。
4. 服务端核对完整清单、哈希、记录数、统计和账号关联后，原子发布新数据代。校验失败保留上一代，不拿空值覆盖历史。
5. 页面读到新代后自动读取已校验分区，保留当前搜索、排序、分页和日期任务。普通资料更新不需要再次打包前端。

运行链路使用普通脚本、HTTP 和数据库，不调用模型。没有新增定时任务；仍由现有来源 worker、采样服务和发布服务运行。

## 边界与排查

- 原表的发布时间不等于指标观测时间。未注明观测日期的累计值不能生成某一天的增长。
- 来源登记不等于平台采样成功。主页、完整作品、话题双指标覆盖分别检查；估算播放不标成实际播放。
- 公开投影不包含原件、授权、登录态、奖金或私有来源链接；原始资料和证据仍在私有主库中。
- 仅当旧的已发布数据代明确没有新来源分区时，页面兼容读取旧静态文件。新代读取失败会显式报错，不静默退回旧数据。
- 汇总校验拒绝不应重传全部已核验数据。发布器保留固定错误类别与上传检查点；恢复后先核对既有代。
- 当前完整作品接口 403 仍需继续解决。本链路没有把原表更新、测试通过或公开发布当作全量平台采集成功。

核心文件：`lib/public-table-foundation.mjs`、`lib/public-source-marker.mjs`、`lib/replica-foundation.mjs`。历史静态重建工具 `frontend/scripts/export-table-foundation.mjs` 保留作旧版复现，日常更新由主库发布器负责。
