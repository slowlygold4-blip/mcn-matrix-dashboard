# 作者作品分区有界读取

真实公开页面的作者作品窗口原本串行读取全部来源作品分区：一位作者的加载也会等待整个来源目录的网络往返。已有来源详情页采用四分区一批，两个界面却各自维护不同的读取循环。

现在共用 `readSourceParts`：每批最多四个请求，结果保持清单顺序，仍逐分区校验长度、SHA、修订和行数，再核对完整目录及严格作品归属。重复路径、非法或混合发布截面在网络请求前拒绝。进度只显示已核验分区数；没有显示半套作品或改用未经验证的缓存。

来源读取共用 60 秒总期限，每分区保留原有独立期限。分区失败会取消同批尚未完成的请求；关闭窗口停止后续读取；手动重试重新核验。总期限只覆盖来源作品分区，后续账号作品分区仍使用其既有独立期限，不能把它称为整个窗口的严格 60 秒上限。单分区及索引原有成功/取消语义保留。

377 项前端测试、7 项相关浏览器流程、类型检查和生产构建通过。新增覆盖四并发上限、逆序完成但输出不乱序、坏分区取消同批、关闭取消、总期限、清单预检、空集合、真实零/缺失及失败重试。实页测量一次请求链路约 20.0 秒降至 7.9 秒，新窗口约 8.0 秒完成展示；这不是统计性能保证。同一作者完整导出在修改前、本地新构建及公开 V140 中逐字节相同。

公开实页还核对了排序、第二页、空搜索恢复、Escape 焦点恢复，以及 390px/320px 详情页边界和页面横向溢出。该阶段没有修复抖音逐作品采集、补历史或增加采样；页面所显示的既有点赞与发布日期不会因此变成当天新观测。
