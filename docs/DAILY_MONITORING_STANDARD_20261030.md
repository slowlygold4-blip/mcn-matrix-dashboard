# 日常采集验收标准

按用户最新确认，日常监控以以下四项验收，覆盖全部作者名册及每个已确认账号；尚未关联的作者保留在名册并显示待关联，不能从分母中消失。

| 采集项 | 保存值 | 变化与完成条件 |
|---|---|---|
| 账号粉丝 | 作者身份、粉丝数、真实观测时间 | 同一账号相邻北京日的有效观测相减；缺当天或前日数据时变化为空 |
| 单作品点赞 | 平台、作者、作品ID、点赞数、真实观测时间 | 每日采用该作品最后一次有效观测，与前一日相减；每条作品独立，不用账号总获赞替代 |
| 账号总获赞 | 主页总获赞、真实观测时间 | 同一账号相邻北京日的净差；不把已收录作品的点赞相加冒充主页总获赞 |
| 每日发布 | 作品ID、作者身份、发布日期或精确发布时间 | 按北京日、作者、作品ID去重计数。采到至少一条即可确认已发布；只有该日列表覆盖证据充分且计数为0时才能确认未发布；否则是待确认或已知条数下限 |

通用要求：

- 从2026-09-12开始长期积累。真实历史保留；缺日不补零，不把恢复采样写到离线日期。
- 表格、API及其他已核验来源进入同一作者/作品集合。身份、作品去重和观测日期对齐后更新，重复累计值不叠加。
- 作品发布日期与指标观测时间分别保留，不能把后来的点赞累计值回填到作品发布日。
- 同一天多次采集保留原始记录；按日展示取最后一次有效值。真实0、负变化保留，缺基线显示原因。
- 粉丝、总获赞、单作品点赞与每日发布分别统计采样覆盖。主页请求成功不代表另外三项齐全。
- 采集、去重、日计算和自动发布运行时不调用模型。开发、研究对话本身不属于零token采集运行。
- 不使用本机抖音浏览器采集；公开/授权HTTP与现有来源同步继续使用各自真实权限，不绕过限流或验证。

## 本轮已落地

原作品指标弹窗只有历次采样值。本轮在同一弹窗增加“单作品每日点赞变化”，默认显示每日计数、日净变化、两个真实采样时间、缺测日期和采样次数；原始记录仍可切换查看，两个视图均可导出。

代码：frontend/lib/work-daily-likes.mjs、frontend/components/work-likes-history.tsx。缺日用连续日期范围记录，避免长期留存时为每个空日创建对象。结束日没有观测会明确显示缺测；最近一次历史点赞不会套用为结束日数值。加减采用两次观测的净差，今日数据标明未结束，不冒称全天新增点赞。

13组新增纯计算/真实组件静态渲染回归，完整前端330项通过；涵盖北京午夜、同日多次采样、缺值、0、负数、跨日缺口、不同作品/账号隔离、重复或冲突观测、固定版本CSV。真实已发布历史另在资料持有者本机逐分区校验字节/SHA并与独立计算比对，不把其中业务明细提交公开仓库。

这项呈现和计算修复不等于平台采集缺口已补齐。完整作品列表、每日单作品刷新率、全部作者身份接入仍需用真实采集回执验收。当前未完成实际页面点击/手机验收，未启动自动浏览器。
