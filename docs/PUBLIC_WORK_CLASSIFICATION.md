# 作品内容分类的公开传递

## 问题与修复

后台已按明确来源证据分类的作品，在公开导出时丢失了 `classifications`。作品仍可被读取，但无法从切片内容筛选中找到。公开作品契约现在允许一个可选、有限枚举的分类数组：`slice`、`original`、`ai-remix`、`contest`。旧记录仍按原契约校验，其余未知字段继续拒绝。

内容分类与激励赛道各自保留。明确归为切片，不代表参加过切片激励计划；已确认的激励赛道可以提供内容类型依据。不得按昵称猜分类，不修改作品的日期、点赞、播放或归属记录。

消费者先部署兼容读取，再升级导出器至 `catalog-date-range-v16-source-work-classification`。原封存代际不重写。前端沿用现有选择器、列表和导出入口，新增内容分类选项与CSV列；原CSV列顺序不变。

## 验证

- 消费端：严格可选字段、错误枚举、重复分类、未知私有字段、旧记录、过滤、URL还原及CSV。
- 真实只读生产预检：使用相同公开脱敏规则与固定截止，核对全部既有作品的12个原字段不变，检查目标作品分类透传和缺失日期保留。
- 发布端：内容密封、源版本指纹、提交证据及新旧导出版本兼容回归。
- 发布后还需按新代际的清单逐字节和SHA读取公开分区，才能声明实际数据已生效。构建通过不代替该步骤。

## 日常监控边界

本修复是已有数据的分类传递，不是采集恢复。日常采集继续按粉丝及变化、逐作品点赞及变化、主页总获赞及变化、每日实际发布情况四项分别验收。只刷新主页不能代表单作品已刷新；历史来源记录也不能当作当天新采样。缺测不补零，作品存量变化不当发片数。运行时不调用模型。
