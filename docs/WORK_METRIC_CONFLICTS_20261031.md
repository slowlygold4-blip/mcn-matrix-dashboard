# 同时刻作品指标冲突

同一作品的两条平台记录可能用 UTC 和带时区偏移的字符串表达同一个时刻。旧作品读模型按记录编号选其中一条；这会让列表、作者合计和发布台账采用任意数字，与既有的每日点赞冲突判定不一致。

现在按真实时刻分别归并点赞和播放：相同值仍是一条有效观测，不同有效值保留冲突。冲突时当前采用值为空，沿用已有 `conflict` 状态及汇总冲突计数，不拿旧表累计、旧平台值或 0 替代。两次平台观测对比的任一端有冲突时不计算差额。同一时刻后来出现一条相同记录不能消除已经发现的矛盾；更晚取得的有效观测可以正常成为新值，真实 0 和下降保留。

按作品和严格作者归属合并的原有条件、发布日期、人工分类、来源原件、历史观测与数据库结构均未改变。来源有明确指标采样时间时仍参与同一取值规则；来源刷新时间仍不冒充采样时间。没有新增采集、模型调用或后台调度。

验证包含两条先失败后修复的复现测试，以及列表、作者合计、发布台账、时区等价、相同值去重、冲突持续、更晚有效值、零值、负差额、独立指标和历史截止。相关 13 文件 115 项测试通过。旧零值语义测试夹具在未修改的正式代码上也有 4 项失败，原因是未支持已有的事务变更计数与流式读取；只更新夹具能力，保留业务断言。

真实数据库的只读核查未发现此类已存同刻矛盾。本修复不声称补齐缺失作品、恢复抖音作品接口或完成全部日常监控；真实数据回读与服务加载结果保存在私有维护记录。
