# 采样成功与作品完整性：推断和计数转换审查

本轮继续第三方验收视角审查。上一轮v127解决待核账号目录只显示前20条的问题；本轮处理其底层的状态真实性和计数转换。**这些修复不解决抖音作品接口拒绝，不代表全集采样已经恢复。**

## 发现与修复

### 单页不等于全集

旧 `deriveCollectionHealth` 在没有显式覆盖状态时，只要找到作品数组就推断 `complete`，不管账号有42个作品、本次只返回1个，或是否还有下一页。仅有主页作品存量0、没有任何作品列表，也会被推断为完整。

现在非空列表最多推断为 `limited`。即使列表长度碰巧等于存量、或单个响应标记终止，也不据此推断全部历史完成。只有原有“显式空列表且真实存量0”的窄兼容情况保留；多个容器中只要还有非空列表，就不能按空账号处理。采集器显式提供的覆盖声明仍保留，最终是否完整继续由原身份、原始响应、分页及库存验证器判定，没有放宽发布门槛。

显式 `unknown` 不再因数组存在被升级。`collectionHealthLabel` 也只对明确 `complete` 返回完成标签，缺失、未来或未知状态显示待判定。该标签函数当前不是公开Site完整性面板的证据来源，不能宣称此前公开面板曾把全部账号报成完成。

### 没有指标不能算主页部分成功

旧逻辑收到 `accountStatus=partial` 时，即使全部指标都缺失仍返回partial。现在至少要有一个真实的非负安全整数才能判为部分可用；真实0仍然有效。失败、身份不匹配、有限观察和过时状态继续独立处理。

这不把“主页部分可用”改名为“三指标完整”。原严格覆盖仍要求粉丝、获赞、作品三个计数同时有效，主页可用率与严格完整率继续区分。

### 计数不允许强制转换或四舍五入

沿调用链发现 `asNonNegativeInteger` 使用 `Number(value)` 和 `Math.round`，会把false/空白/空数组转换成0、true转换成1、1.5转换成2，还可能接受丢失精度的巨大整数。

检查全部运行、工具和测试引用后，确认该函数只用于规范化计数和账号快照源向量验证。现收紧为非负安全整数，或trim后只含十进制数字的字符串；不改变配置或日期转换。缺失和非法输入继续返回null，真实0及可精确表示的数字字符串仍保留。

话题的缺失作品总数不再拿本次作品样本条数代替；话题页面仍只关注真实参与人数和实际播放量。原始输入和作品记录保留。

## 验证证据

1. 第一组10项回归在旧代码中8失败、2通过；随后新增的3项严格计数回归全部先失败。另补话题缺计数不使用样本量的回归。最终14项新增回归全部通过。
2. 27个相关测试文件共412项通过，并在原后台代码目录重复同组通过。范围包含规范化、调度、分页、作品覆盖、公开覆盖、来源完整性、数据库、话题和SLA；两次运行不是824项独立测试。
3. 调度测试有一项原先把无分页证据的单页响应计为0警告；修复后应为1个有限观察提示，现保留请求次数、重试隔离和成功/失败计数断言，并新增reviewState=limited断言。没有给合成样例伪造完整分页证据来维持旧“完成”结果。
4. 同一个正式只读数据库事务，逐条对比全部129,097条已保存账号快照：校验值匹配129,097，手工来源110；粉丝/获赞/作品及逐作品指标差异0，账号来源验证结果变化0。只有1,455次旧完整推断应降为有限观察。**这是读取逻辑对比，没有重写1,455条历史记录，也不等于新增采样。**
5. 全部445条话题快照参与人数和实际播放量规范化差异0。以上两组均0数据库写入、0平台请求、0模型调用。

代码、只含汇总的正式库对照与发布记录见 [证据目录](audits/2026-10-30-health-inference/)。旧基线为公开源码6627082；对照时原后台仍加载旧版，完成对照后才同步新文件。全库对照的结论限于这个真实截面，不能代替未来数据的来源核验。

## 发布与剩余工作

关键文件先备份；已有SQLite一致性快照经SHA256、quick_check、临时硬链接读取及六表行数核对。同步代码后，在原后台目录再次通过412项测试。首次发现有正在运行的采集批次，未同步或重启；确认批次结束后才更新，并在空闲窗口通过原launchd平滑加载。没有新增采集器或调度，没有开启浏览器，没有修改名单、历史、原始响应和来源记录。

原服务正常启动会生成一次新的完整数据库备份，这次磁盘占用不能写成零；临时验证硬链接没有额外复制整库。主服务加载及新备份验证以release.json和私有交接记录为准。公开网页保留v127，本轮没有前端发布。

仍需解决作品全集的真实采样、未关联作者、连续每日历史及剩余内存峰值。当前公开覆盖已经采用更严格的分页证据，所以不能把本轮规范化缺陷说成线上403或当前完整作品0的根因，更不能宣称提升了实际采样成功率。
