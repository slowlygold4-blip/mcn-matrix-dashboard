# 作品归属在总览、作者详情和导出间保持一致

原始表的作者声明保留，但当同一作品已由严格的平台证据核验为其他账号发布时，不能继续算入原声明作者的累计指标或每日发布数。

## 数据与界面

在现有公开目录 `creatorSourceLinks` 下增加可选 `workOwners` 数组：`workRow / contentId / targetId`。它只关联某条作品与已核验发布者，不关联或合并两个作者身份。来源版本、源行与作品 ID、目录账号、真实数字编号的平台作品分区都须一致；合成的来源记录不能充当平台发布者证据。未知字段、重复行或作品、不同版本、缺失作品分区均拒绝。旧版本没有此数组时保持原契约，不追加作品分区读取。

现有作者作品弹窗直接消费该映射：

- 原声明作者：保留作品与原始数字，标明未计入该作者统计；每日发片不据此判断已发布。
- 已核验发布者：同作品只出现一次，采用有效观测，原归属冲突的累计值单独作为未采用证据保留。
- 提供查看已核验发布者的入口，使用原账号页面与固定版本导航。
- 搜索、排序、分页、合计、日查看和 CSV 使用同一作品集合；导出包含归属状态、发布者账号编号和原声明冲突数字。
- 新数据版本读取期间不把上一版本的作品临时显示为新版本结果；未关联作者用稳定行身份区分，避免同为空 ID 时复用旧弹窗数据。

原始来源、历史数据、作者启停和身份均不改写。运行中只是确定性脚本和前端计算，不调用模型。

## 验证与限制

新增六组所有权、指标、日计数和实际源发布审查回归；完整前端349项、类型检查与生产构建通过。后端新增真实合成导出闭环，检查原作者声明未改、只有作品映射变化，并拒绝伪造导出来源证明。真实资料验证及部署状态另记维护日志，不将合成测试称作平台成功率。

先发布兼容读取页面，再启用生产映射。新页面读取没有映射的旧代际时不会虚构归属；等待既有串行发布流程生成新代际后，必须再次核对映射和公开数据才能声明实际生效。作品每日采集缺口不因本次归属改进而消失。Work设置禁用浏览器，未进行实际点击/手机浏览验收。

## 本轮构建资源审查

历史编译资源累计触及64MiB保护上限。本轮未提高上限：按v128、v129、v130的新增资源，加当前Vite输出及其完整依赖闭包，先用原始保留校验器在临时目录验证，再清理705个过期的可再生成资源文件。原清单与Git HEAD完全一致，可从历史恢复。业务资料、原表、数据库、源码及Git历史未删除。

清理时原归档67,078,197字节，精选3,953,210字节；后续当前构建合并后约5.2MB。后续仍由相同保护上限拦截异常增长，超限时审查当前与最近部署依赖链，不能无限提升上限。非常旧的已打开页面可能需要刷新以切换当前版本；不承诺永久托管所有历史前端资源。
