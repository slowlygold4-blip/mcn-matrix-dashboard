# 完整性问题账号：从前20条变成可遍历的目录

审查发现，完整性面板对当前已选范围的全部待核账号计算总数，却只渲染前20条，没有后续入口。管理者无法在这个问题目录里找后面的账号，只能另到账号页逐条核对。

本次修改保留原视觉和证据口径，补齐完整工作流：

- 按账号名称、内部编号查找；搜索覆盖所有待核账号，不限当前页。
- 筛选主页过时或缺测、作品尚未完整、最近尝试未取得、尚无有效观察、仅有限观察。
- 每页20条，支持首页、前后页、页码直达与末页；条件改变返回第一页。
- 保留原本的可行动问题优先级，按真实尝试时间排序；日期字符串的整秒与毫秒不能改变时间先后。
- 显示全部待核数、筛选结果数和当前范围；无搜索结果不显示为没有采样缺口。
- 刷新或切换范围后页码会被约束到有效页，避免空白页；每次最多渲染20个详情入口。
- 所有账号入口沿用原详情与返回流程，不启动采集、不改数据、不新增数据源板块。

证据层没有变化：主页、作品、话题分别统计；名单可见不等于采样成功；过时或有限作品观察不会升级为完整。

验证：新增7项回归，包括4,081条合成问题账号遍历205页、每个ID恰好出现一次、全部问题筛选、跨页搜索、空结果、顺序和React首屏渲染。非浏览器前端整套317项通过，TypeScript通过。生产构建与发布以交接记录为准。

Work设置关闭了本机浏览器，cua返回 `Local browser use is disabled in Work settings`。本轮未绕过设置启动其他浏览器，React静态渲染与纯函数测试不能代替真实手机、键盘或点击验收，不能称这些场景已实测完成。

整体目标仍未完成：作品全集采样仍受阻，尚有身份关联和历史每日完整性缺口。本次让问题可查可定位，不把界面改进写成采样恢复。
